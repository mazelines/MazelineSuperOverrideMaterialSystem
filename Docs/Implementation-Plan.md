# Mazeline Super Overrider Material 구현 단계

목표 엔진은 Epic 설치형 UE 5.8.4이며, 에디터와 패키지에서의 동작을 각각 검증한다. 머티리얼의 연결된 Custom Expression에서 `MAZELINE_SHADER_OVERRIDE`를 정의해 참여 여부를 표시하고 Base Color, Roughness, Metallic 입력을 사용한다. 사용자가 작성한 HLSL 함수는 광원 방향을 받아야 한다.

1. **환경과 패치 상태 확인:** 엔진 버전, 셰이더 파일과 삽입 지점, 기존 패치 여부를 진단한다. 지원하지 않는 버전이나 예상과 다른 원본은 수정하지 않는다. 에디터 명령과 빌드 결과를 확인한다.
2. **패치 관리:** 엔진 원본을 백업하고 정확히 확인한 위치에만 패치를 적용한다. 중복 적용을 방지하고 외부 변경이 있으면 복구를 중단한다. 적용·복구·충돌을 테스트한다. 기능이 검증되기 전에는 자동으로 엔진에 적용하지 않는다.
3. **Forward 실험:** 선택된 머티리얼에서만 사용자 함수가 광원 방향과 머티리얼 입력을 받아 실행되는지 검증한다. 다른 Default Lit 머티리얼과 두 개 이상의 광원도 비교한다. 함수 시그니처와 이용 가능한 입력은 실험으로 확정한다.
4. **Deferred 실험:** 머티리얼 식별자와 필요한 데이터를 전달하는 채널을 찾고, 공유 광원 셰이더에 사용자 함수를 등록·선택하는 경로를 구현한다. Base Color, Roughness, Metallic을 보존한다. 사용 가능한 함수 입력, 텍스처와 함수 수의 제한을 명시한다.
5. **통합과 배포 검증:** 선택하지 않은 머티리얼의 회귀, 에디터 재시작, 셰이더 재컴파일, 패키징과 패치 복구를 검증한다. Forward와 Deferred를 각각 테스트하고 확인되지 않은 렌더링 경로는 지원한다고 표시하지 않는다.

1~5단계 구현 및 Windows DX11/SM5 Opaque Default Lit 범위의 검증을 완료했다. 두 렌더링 경로에서 입력 보존, Roughness 출력 변경, 일반 머티리얼의 원본 엔진 대비 비교, Win64 Development 패키징과 실제 실행을 확인했다. 정량 결과와 근거는 `Validation-Results.md`에 정리했다. 통합 관리 도구의 원본 백업은 엔진의 `Engine/Saved/MazelineShaderOverride`에 보관한다. 이전 프로젝트 `Saved`의 실험 백업은 이력으로 유지한다. 지원 범위와 사용법은 플러그인의 `README.md`를 참조한다.

## 0.3.0 C++ 통합 단계 — 완료

6. **기존 데이터 호환:** Python format 1의 원본·적용본·소유권·중단 기록과 SHA-256을 C++으로 읽는다. 기존 엔진 백업으로 호환성을 검증했다.
7. **네이티브 패치 관리자:** 함수 수집과 셰이더 생성, 엔진 단위 잠금, 원자적 파일 쓰기, 복구 저널을 C++으로 구현했다. 오류 주입 테스트로 적용·갱신·복원 중단과 외부 변경 거부를 확인했다.
8. **프로젝트 설정:** Plugins → Mazeline Super Override Material에 상태, 적용·갱신, 복원, 중단 복구, 백업 열기, 재시작을 등록했다. 실제 화면에서 상태 전환과 엔진 파일 변경을 확인했다.
9. **실제 엔진 검증:** Python 비활성 상태에서 자동 테스트 5개와 커맨드릿 복원·재적용을 통과했다. 생성한 셰이더 세 파일은 기존 GPU 검증본과 바이트 단위로 같다. 세부 결과는 `Native-Patch-Validation.md`에 기록한다.
